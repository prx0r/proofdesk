## 0. Review of the 6-Experiment Suite (`run_all_experiments.py`, verified by execution)

### E1 Risk Classification — 96.5% CV: LEAKAGE, result is tautological

Features fed to logistic regression:
```python
[c/10000, r/10000, abs(c-r)/1000, has_discount, edge_case]
label = abs(c - r) < 0.01        # correct_total vs rendered_total
```
The third feature is the label up to a threshold — the classifier is doing arithmetic on numbers it is handed. There is no extraction uncertainty anywhere in the loop: both totals arrive as clean inputs. This measures *"can LR compare two floats"*, not *"can we trust an extracted document enough to sign it."* The 96.5% (not ~100% only because of near-tie noise) will not survive review.

**Fix:** the model must see only what a deployed system sees: Nutrient extraction output over the document image/PDF (extracted values + per-field confidences), never the ground-truth total. See §A below for the corpus that makes this possible.

### E3 False-Sign Tradeoff — coverage ≡ α by construction; inconsistent with E6

Output shows coverage tracking α almost exactly (1%→1.0%, 5%→5.0%, 10%→10.0%) with FPR=0 everywhere — the threshold selection is effectively selecting the top-α fraction, i.e., restating the input as the result. Meanwhile E6 reports 3 false signs at 81% coverage: different operating assumptions across experiments with no reconciliation.

**Fix:** define one risk-control rule (CRC on held-out calibration split), report the full risk–coverage curve, and use identical operating rules across E2/E3/E6.

### E4 Per-Type Analysis — degenerate
Single doc type (invoice, n=200). The per-type story needs ≥2 types; FATURA/FUNSD loaders already exist in `ml_pipeline.py`.

### E5 Merkle Audit — fine
Chain valid, deterministic. No issues.

### E6 End-to-End — the only experiment with external validity, but inherits E1's leakage via shared features.

## 2. Validity Threat

### 2.1 Simulated Nutrient signals (circularity risk)
The "multi-signal fusion beats single-signal by 11× on Brier" result runs on `signals.py` — a *simulator* of Nutrient-style confidences. If simulator noise/correlation parameters were chosen after seeing desired separation, the 11× is encoded, not discovered.

**Fix (P0):** replace simulated signals with real ones. The parent repo (`proofdesk/`) already extracts real Nutrient confidences across 118 docs (`benchmark_proper.py`). Capture `(per-field confidence, match label, page count, doc type)` tuples to a frozen JSONL and fit calibrators on that. Keep the simulator only as a unit-test fixture.

### 2.2 Sheepish metric may leak ground truth
`sheepish.py`: `s* = (λ_over·c + λ_under·a)/(λ_over+λ_under)` where `a` = field accuracy. If `field_accuracy` at inference comes from labels, the transform sees the answer. Legitimate only if `a` is *estimated* (e.g., held-out accuracy for that doc-type/world) at decision time.

**Fix (P0):** audit call sites; document that `a` must be an out-of-sample estimate. Add a test asserting sheepish score never improves discrimination over raw score when `a` is oracle — if it does, there's leakage.

### 2.3 Coverage collapse
Per-world optimal thresholds yield 6–16% coverage on `confounded_choice`/`regime_flip` at ~0 risk. You capture 27% of oracle utility (0.107/0.396). Either α is too strict for those worlds or the loss model over-penalizes misses. Report **risk–coverage curves + AURC** per world, not just the operating point; sweep α ∈ {0.02…0.20} and show the frontier. Otherwise reviewers read "defers everything" as a null result.

## A. Doctavian → the fix for E1's leakage: controlled-complexity corpus

Doctavian's core innovation (templates that **branch, loop, and calculate**) is exactly what the lab lacks: a way to generate documents where **extraction difficulty varies while ground truth stays exact**. This closes the leakage gap in E1/E3/E6.

**Protocol — "difficulty ladder" corpus:**

1. Parametrize one invoice template along axes of real difficulty:
   - line-item count (loop): 1 → 50 items
   - conditional discounts/tax rules (branch) that change which arithmetic applies
   - calculated totals (calc expressions), including **near-misses**: totals off by ±0.01 rounding, transposed digits injected into data *before* rendering so the rendered document itself contains the error
   - locale/timezone variants (their Mission 3 pattern)
2. Ground truth = the JSON you sent + Doctavian's deterministic computation. Exact by construction, at every difficulty level.
3. For each doc: render (Doctavian) → optionally degrade → extract (**Nutrient only sees the PDF**) → score (lab module sees only extraction outputs + confidences).
4. Now E1 measures the real question: does confidence track true document difficulty? Plot ECE/Brier vs ladder rung; FPR/FNR on near-miss strata specifically.
5. Rebuild E3 as a genuine CRC tradeoff on this corpus; reconcile with E6 operating point.

Client ready at `../src/providers/doctavian.py::DoctavianClient`; workflow/creds per `../docs/DOCTAVIAN_API_REFERENCE.md`. **Cache rule:** generate once, commit PDFs+manifest, experiments offline forever.
